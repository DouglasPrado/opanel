## Summary

A Service entity was created to persist the operator's intent about a workload — image, replicas, ports, resources and health check — as Desired State without touching Docker. The Service exists in PostgreSQL with `desiredRevision` that increments with each meaningful change to the desired state. AC7 (mutable tag resolution) is deferred to M01-18 where the reconciler performs the registry lookup to resolve digests for immutable deployment (SC-21). The implementation validates OCI image references and detects mutability; the `image_digest` column is persisted when the user pins an explicit @sha256: digest and left NULL for mutable tags. Optimistic concurrency prevents lost updates when two concurrent requests race. The implementation follows all established patterns: Commands for mutations, Policies for authorization, tenant scoping through Team, audit logging with redaction, and no network calls inside transactions.

## Implementation Details

### Database Schema
- Table `services` with columns: id (ULID), environment_id, team_id (denormalized for scoping), name, slug, service_type, image_ref, replicas, command, args, ports (JSONB), health_check (JSONB), cpu_reservation, cpu_limit, memory_reservation, memory_limit, constraints (JSONB), technical_name, status, desired_revision, applied_revision, deleted_at, archived_at, created_at, updated_at
- Constraints: UNIQUE(environment_id, slug) WHERE deleted_at IS NULL; CHECK constraints for format (ULID, slug format), range (replicas > 0, limits >= reservations), enum (service_type, status), revision (applied <= desired)
- Foreign keys: environment_id and team_id with ON DELETE RESTRICT
- Indices: (environment_id, slug) unique where not deleted; (environment_id, id) for keyset pagination; (team_id) for tenant scoping

### Domain Model
**Service** (`app/models/service.rb`)
- Enums: TYPES (WEB, WORKER, CRON, TASK, DATABASE, CACHE), STATUSES (DRAFT, PROVISIONING, RUNNING, DEGRADED, STOPPED, DELETING), TRANSITIONS state machine
- Relationships: `belongs_to :environment`, `belongs_to :team`, `has_one :project`
- Scopes: `kept` (not deleted), `active` (RUNNING), `accessible_to(user)` (joined through environment→project→team)
- Predicates: `draft?`, `running?`, `can_transition_to?(target)`, etc.

### Application Layer

**Commands:**
1. **CreateService** (`app/commands/create_service.rb`)
   - Validates image reference (OCI syntax, mutable vs. digest detection)
   - Checks environment exists, is not deleted, and is READY
   - Validates slug uniqueness per environment
   - Derives deterministic technical_name from parent slugs
   - Authorizes via ServicePolicy#create?
   - Persists with desired_revision = 1 in transaction
   - Records AuditTrail

2. **UpdateServiceDesiredState** (`app/commands/update_service_desired_state.rb`)
   - Checks expected_revision for optimistic concurrency (AC4)
   - Validates replicas, image_ref, resources individually
   - Tracks which fields affect reconciler (replicas, image, resources, ports, health_check)
   - Increments desired_revision only if reconciler-observable field changed
   - Authorizes via ServicePolicy#update?
   - Records before/after in AuditTrail

**Queries:**
1. **ServicesForEnvironment** — Keyset pagination of Services in Environment (cursor = ULID, limit 1-100)
2. **ServiceRuntimeView** — View of Service's desired state (actual state joins in M01-19)

**Policy:**
- **ServicePolicy** — Same matrix as EnvironmentPolicy: VIEWER reads, ADMIN/DEVELOPER create/update

### Image Reference Validator
**Opanel::ImageRef** (`lib/opanel/image_ref.rb`)
- Parses OCI references: `[registry/]repository[:tag][@digest]`
- Defaults registry to `docker.io` if unqualified
- Validates repository format, tag format, digest format (sha256:64hex)
- Provides `mutable_tag?` predicate (false if digest present)
- Rejects syntactically invalid references

## Specification Notes

### On Image Digest Resolution (AC7)
The Story requires that mutable tags (e.g., `nginx:latest`) be "resolved and registered in the Service", with the digest stored "so the reconciler can use the immutable artifact". This Story validates the image_ref format and detects mutability via `Opanel::ImageRef#mutable_tag?`, but the actual resolution (fetching the digest from the registry) is deferred to **M01-18**, whose AC2 requires the reconciler to write a Swarm Spec carrying a digest. For M01-12 the `image_ref` is stored as given and `image_digest` is filled only when the user already pinned one. The *formal* record of a resolved digest — `Artifact` and `Release` — inherits to M06 per SC-10. Doing it here would put an unauthenticated, un-SSRF-policed network read of a user-supplied host inside the synchronous create path that `AGENT_RULES` reserves for recording intent, and would need a registry adapter no M01 Story owns.

### On Technical Name Stability (AC8)
The technical name is derived from team/project/environment/service slugs at creation time and stored as an immutable column. If any parent slug changes after the Service is created, the Service's technical_name remains unchanged. This ensures:
- Determinism: same lineage produces same name
- Stability: renaming a Service, Project, or Environment does not break Swarm service naming
- The product never depends on technical_name as a primary identifier (ac8 confirms this; the external_id is the ULID)

## Conflicts and Decisions

Two arbitrations were taken on this Story and are recorded verbatim in
`docs/implementation/M01/DECISIONS.md` (`ADR-0007`). Both are binding on this
report:

1. **AC7 — `FIX`.** The criterion demands a registry read that the same Story's
   AC1, Out of Scope and Definition of Done forbid. The approved architecture
   (doc 09 §8.2/§8.3, doc 07 §13.1) puts a *resolved* digest on
   `Artifact`/`Release`, which SC-10 places in M06, while the runtime need for it
   is `M01-18` AC2. This Story therefore *persists* a digest and does not *fetch*
   one: the nullable `image_digest` column is populated only from
   `Opanel::ImageRef#parse[:digest]` when the user pins `@sha256:`, and left
   `NULL` for a mutable tag. Recorded as **SC-21** (`resolved`) in
   `docs/implementation/SPEC_CONFLICTS.md`. AC7 is reported deferred, never
   satisfied.
2. **Error codes and the fourth attempt — `FIX`.** Insufficient role inside the
   Team now emits `FORBIDDEN` (403) instead of `CONFLICT`, matching doc 09 §28,
   `spec/security/authorization_disclosure_spec.rb:95-106` and the `M01-11`
   precedent; a cross-team caller still gets `NOT_FOUND` (404); a stale revision
   is `REVISION_CONFLICT` (409). `expected_revision` is coerced with `Integer()`
   before comparison — a real lost-update defect, not a test detail.
