## Decisões locais

1. **SQL Parameter Binding with exec_query**: Changed from `execute()` to `exec_query()` for proper positional parameter binding in PostgreSQL. The `execute()` method does not support `$1, $2` syntax in the way we needed.

2. **Time Handling in Result Mapping**: After raw SQL insertion, reload the ResourceLock from the database using `ResourceLock.find()` so ActiveRecord recognizes the row for subsequent `.update!` calls. This prevents duplicate key errors in test cleanup.

3. **Fencing Token Detection**: Use `rl.fencing_token > 0` to detect takeover. Fresh INSERT sets token to 0 (parameter); UPDATE increments from prior value, so > 0 proves UPDATE occurred, not INSERT.

4. **Operation::InvalidTransition Exception**: Made the exception class accept both (from_status, to_status) and (message_only) signatures to support both state-transition errors and fencing-specific validation errors.

5. **Concurrent Test Fixture Setup**: Use `unique_namespace` with additional `SecureRandom.hex()` for both email and team slug to prevent duplicate key errors when concurrent tests run. Wrap Team + TeamMember creation in transaction to defer FK check.

6. **Test Cleanup Order**: Delete Team before TeamMember when cleaning up, because Team has FK to TeamMember (OWNER requirement). Deleting Team first (which cascades) avoids FK violations on explicit TeamMember.delete.

7. **RSpec Matcher Syntax**: Changed `.to have(N).items` to `.count.to eq(N)` for RSpec compatibility within concurrent blocks where the matcher context may not be available.

## Acceptance Criteria

- [x] 1. Mutation serialization — `spec/integration/resource_lock_serialization_spec.rb:39` — Two concurrent workers on same scope, one acquires, one blocked until release
- [x] 2. Concurrent mutations serialized with barrier — `spec/integration/resource_lock_serialization_spec.rb:39` — Barrier ensures both threads ready; exactly one succeeds; serialization proven
- [x] 3. Fencing token monotonic per scope — `spec/unit/fencing_token_spec.rb` — Increments on each acquisition; concurrent increments under row lock
- [x] 4. Stale token rejected — `spec/integration/resource_lock_fencing_spec.rb:21` — Central test: worker 1 acquires token N, loses lease, worker 2 takes over with N+1, worker 1's attempt with N is rejected
- [x] 5. Lease released after operation result — `spec/integration/resource_lock_ttl_expiry_spec.rb:65` — `ReleaseResourceLock` idempotent; test shows takeover only after release
- [x] 6. Successor revalidates before acting — `spec/integration/resource_lock_successor_revalidation_spec.rb` — Fenced write refused if `took_over=true` but `observation_recorded=false`; passes after `record_observation!`
- [x] 7. TTL guarantees release — `spec/integration/resource_lock_ttl_expiry_spec.rb` — Worker disappears (no explicit release); lease expires; successor acquires with incremented token
- [x] 8. Concurrent reads not blocked — `spec/integration/resource_lock_concurrent_reads_spec.rb` — Multiple readers execute while one writer holds lock; reads succeed with no wait
- [x] 9. Events observable — Structured logs in `AcquireResourceLock.call`, `RenewResourceLock.call`, `ReleaseResourceLock.call` with `scope_key`, `owner`, `fencing_token`, `team_id`
- [x] 10. Owner not from client — `spec/security/resource_lock_owner_spec.rb:9` — `Opanel::WorkerIdentity.current` used; never accepts owner parameter
