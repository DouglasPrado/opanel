## Implementation Details

### Item (1): Fix Service ID in Ownership Labels Test

**File:** `spec/integration/swarm_ownership_labels_spec.rb:78`

Changed `resource_id: service.id` to `resource_id: service.external_id`. The executor's `find_by_label` function receives resource_id in external format (prefixed ULID, e.g., `svc_01ARZ…`). The test was passing internal id format, causing label filter mismatches on retry adoption. Fix aligns with line 115 (network test) which already uses `environment.external_id`.

### Item (2): Fix Unowned Network Test

**File:** `spec/integration/network_unowned_blocked_lab_spec.rb:9-34`

Rewrote test to create unowned network under the exact technical name the reconciler will use: `Opanel::Ownership.technical_name_for(environment)`. This guarantees a name collision, triggering the executor's `RESOURCE_NAME_CONFLICT` response at line 391 of `swarm_executor.rb`. Test now asserts:
- `run.result == ReconciliationRun::BLOCKED`
- `run.error_reason` is present and names the conflicting resource
- `network.status == Network::DEGRADED`
- `network.applied_revision` remains nil (never advanced)

### Item (3): Add RESOURCE_NAME_CONFLICT Handling

**File:** `app/reconcilers/network_reconciler.rb:230-250`

Added explicit case for `ExecutionResult::FAILED` with `error_code == "RESOURCE_NAME_CONFLICT"`:

```ruby
when ExecutionResult::FAILED
  if result.error_code == "RESOURCE_NAME_CONFLICT"
    network.update!(status: Network::DEGRADED)
    run.update!(result: ReconciliationRun::BLOCKED,
               error_reason: "Resource name conflict with unowned network '#{network.technical_name}'; platform never adopts unowned resources")
    log_blocked(network, run)
  else
    # ... other failures
  end
```

This branch:
- Records BLOCKED (never FAILED) per AC6 requirement
- Leaves network DEGRADED (no auto-recovery)
- Never advances applied_revision
- Provides diagnosis naming the conflicting technical name and platform policy

The existing CONFLICT branch at lines 214-228 remains unchanged (handles different case: name conflict detected before create is attempted).

### Item (4): Test Replacement for AC4 and AC5

**File:** `spec/integration/network_reconciler_lab_spec.rb:36-112`

Replaced single test with two:

**AC4 test** (lines 36-75): Runs reconciler twice against clean daemon
- First run: creates network with platform labels, verifies READY status and revision advancement
- Second run: should be NOOP with unchanged swarm_network_id
- **Status:** FAIL — second run gets diff_class CREATE instead of NOOP; inspection not finding network

**AC5 test** (lines 77-112): Network with platform labels recognized as NOOP
- Creates network in Swarm directly with platform labels and technical name
- Runs reconciler once, expects NOOP and status READY
- **Status:** PASS — reconciler correctly recognizes existing platform-owned network, sets status READY, persists swarm_network_id

**AC4 remaining issue:** Second run of reconciler gets diff_class CREATE instead of NOOP. The first run successfully creates the network and sets all fields correctly, but the second run's inspection does not find the network by label. This traces to find_by_label not returning the network on the second search. The network exists in Swarm (verified by lab_resource_exists?) but the executor's label filter is not finding it.
