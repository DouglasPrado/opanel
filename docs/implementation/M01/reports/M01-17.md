## Root Cause Analysis

The AC4 failure ("second reconcile run returns NOOP") was caused by a lease release defect:

- **Cause:** `app/reconcilers/network_reconciler.rb:105` calls `ReleaseResourceLock.call(lock: lock, worker_identity: system_actor.id)`, where `system_actor = User.new(id: "system")`
- **Contract mismatch:** `app/commands/acquire_resource_lock.rb:49` records the owner as `Opanel::WorkerIdentity.current` (e.g., `"hostname-pid-boot_id"`)
- **Result:** The ownership check in `app/commands/release_resource_lock.rb:26-38` fails, lease is never released
- **Second run behavior:** `acquire_resource_lock.rb:95-112` detects an active lease and returns `CONFLICT`, preventing Step 2 (load desired state). The second run never inspects and never creates a `ReconciliationRun`
- **Test observation:** `spec/integration/network_reconciler_lab_spec.rb:71` reads the **first** run's `ReconciliationRun` row, which has `diff_class = CREATE`

This explains all negatives:
- No `inspect_failed` event because no inspection occurred
- No daemon residue
- AC5 green because it runs the reconciler exactly once
- AC4 red because the second run never executes

## Implementation Details

### Item (1): Fix Lease Release

**File:** `app/reconcilers/network_reconciler.rb:105`

Changed from:
```ruby
ReleaseResourceLock.call(lock: lock, worker_identity: system_actor.id)
```

To:
```ruby
ReleaseResourceLock.call(lock: lock, worker_identity: Opanel::WorkerIdentity.current)
```

The `system_actor` method (lines 337-339) was deleted as it had no other callers.

**Rationale:** The worker identity used to acquire the lock must match the identity used to release it. `AcquireResourceLock` records `Opanel::WorkerIdentity.current`, so `ReleaseResourceLock` must pass the same identity. This is a production defect: `ReconcileNetworksJob`'s periodic sweep was stranding a 30-second lease per Environment on every pass, and any trigger inside that window would find an active lease and exit at line 50 without executing the reconciliation.

### Item (2): Update Unit Test Matcher

**File:** `spec/unit/network_reconciler_spec.rb:22`

Changed from:
```ruby
expect(ReleaseResourceLock).to receive(:call).with(
  hash_including(lock: lock_double, worker_identity: anything)
)
```

To:
```ruby
expect(ReleaseResourceLock).to receive(:call).with(
  hash_including(lock: lock_double, worker_identity: Opanel::WorkerIdentity.current)
)
```

The permissive `anything` matcher allowed the test to pass even when the wrong identity was passed. The corrected expectation now enforces the contract: the test immediately fails if line 105 regresses to using `system_actor.id` or any other value.

### Item (3): Add AC12 Example

**File:** `spec/unit/network_reconciler_spec.rb:68-127`

Added new example "re-observes before acting when taking over an expired lease":

1. **Setup:** Pre-inserts a `ResourceLock` row with an expired `lease_until` and a foreign `owner`
2. **Execution:** Runs the reconciler (which calls the real `AcquireResourceLock` to take over the expired lock)
3. **Assertions:**
   - The lock's `fencing_token` was incremented (takeover confirmed)
   - The first executor command is `inspect_network` (re-observation before any mutation)
   - A `create_network` command follows

This example is now possible because the lease is actually released by item (1), allowing a subsequent `AcquireResourceLock.call` to succeed and increment the fencing token.
