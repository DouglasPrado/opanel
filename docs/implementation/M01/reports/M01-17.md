## What Changed

### Item 1: Critical — Ownership Labels

**File:** `app/reconcilers/network_reconciler.rb:183`

```diff
- labels: Opanel::Ownership.labels_for(network),
+ labels: Opanel::Ownership.labels_for(network.environment),
```

**Why:** A `Network` has `belongs_to :environment` but no `project_id` column. The `labels_for` method (ownership.rb:48-52) sets `project_id` only for Services or objects responding to `project_id`. Networks do not. The executor's comment (swarm_executor.rb:460-461) documents the intended contract: `labels_for(environment)`. Pre-existing test `ownership_labels_spec.rb:41-53` (M01-16) proves this yields all four required labels: managed, team_id, project_id, environment_id.

**Test validation:** New test at network_reconciler_spec.rb:67–147 verifies the create command's payload includes all four labels as strings (ExecutorCommand stringifies keys).

### Item 2: High — Executor Stub Contract

**File:** `spec/unit/network_reconciler_spec.rb:25-30, 48-53`

**Before:** Bare `double` with `safe_metadata: { network_data: nil }` — a shape ExecutionResult never carries.  
**After:** `instance_double(ExecutionResult, outcome: …, observed: …)` — a verifying double that fails if a stub encodes a field the class does not define.

**New example (lines 67–147):** "creation with ownership labels" test:
- Inspect returns nil (network absent)
- Create command payload assertion: must include project_id  
- Re-inspect returns observation with proper labels (see Item 3)
- Network converges to READY with applied_revision == desired_revision

This test drives AC2 and AC11 assertions directly in code.

### Item 3: Spec Migration — RuntimeObservation

**Files:**
- `spec/unit/ownership_predicate_spec.rb` (15 examples)
- `spec/integration/swarm_ownership_reidentification_spec.rb` (3 examples)

**What changed (per ADR-0009 §4):** 

The predicate `managed_by_platform?` changed signature from:
```ruby
def managed_by_platform?(hash) # raw Engine JSON
```

To:
```ruby
def managed_by_platform?(observation) # RuntimeObservation
```

**Migration approach:**

1. Added helper methods:
   - `service_observation(engine_service)` → RuntimeObservation
   - `network_observation(engine_network)` → RuntimeObservation

2. Updated all examples to build observations from same Engine bodies:
   ```ruby
   engine_service = service_runtime_resource
   observation = service_observation(engine_service)
   expect(Opanel::Ownership.managed_by_platform?(observation)).to be true
   ```

3. Each positive assertion verifies true (same as before)  
4. Each negative keeps its own specific reason (not just type guard pass)  
5. Type guard test at ownership_predicate_spec.rb:96–99 kept for coverage of ownership.rb:117

**Result:** 18 examples pass; no assertions deleted, inverted or weakened. Migration is strictly stronger coverage.
