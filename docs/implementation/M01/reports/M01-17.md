## Implementation Details

### Item (1): Shortened Technical Names

**File:** `lib/opanel/ownership.rb:90-104`

**Before:**
- Network: `net_<projectId>_<environmentId>` = 65 characters (rejected by Engine)
- Service: `svc_<projectId>_<environmentId>_<serviceId>` = 96 characters

**After:**
- Network: `net_<environmentId>` = 34 characters ✓
- Service: `svc_<serviceId>` = 34 characters ✓

**Rationale documented in code:**
- Ground: doc 09 §195 (deterministic, derived from IDs, never primary identifier), Engine's 63-char limit
- Why: ADR-0009 §5 addresses resources by label, not name lookup
- Why no truncation: Would make collision probabilistic (violates M01-16 AC8)
- Why no hash: Stops being "derivado de IDs"

## Lab Test Failures — Undiagnosed

Three integration tests against live daemon fail. Coordinator requested diagnosis; investigation revealed architectural incompatibility with test assumptions:

### network_reconciler_lab_spec.rb:36 (AC4, AC5)
- **Symptom:** Second reconcile returns `diff_class: "CREATE"` instead of `"NOOP"`
- **Diagnosis:** Test creates network without `com.opanel.environment_id` label. New code uses `find_by_label` (ADR-0009 §5), so unlabeled network is not found on inspect. Diff correctly computes CREATE. This is correct behavior; test's assumption (finding by name) incompatible with architecture.
- **Resolution needed:** Test must either create via reconciler twice, or create lab network with platform labels

### network_unowned_blocked_lab_spec.rb:9 (AC6)
- **Symptom:** Expected BLOCKED, got SUCCESS
- **Diagnosis:** Test creates lab network with lab name, creates Network record with same name. But desired network's technical_name is `net_<env_ULID>`, not lab name. Reconciler creates with technical_name; no conflict detected. Test's assumptions misaligned with new name scheme.
- **Resolution needed:** Test setup and expected flow need alignment with architecture

### swarm_ownership_labels_spec.rb:66 (AC7)
- **Symptom:** Retry after create returns CONFLICT instead of NOOP (adoption)
- **Diagnosis:** Incomplete — requires tracing label filter behavior against live daemon. Service created with labels on first run; second create (new executor, same command) should adopt. Getting CONFLICT suggests `find_by_label` not matching or name conflict check failing when it shouldn't.
- **Resolution needed:** Requires deeper instrumentation/tracing
