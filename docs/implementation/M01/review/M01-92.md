## 2. Boundary and scope

**Finding F-2 (High):** the diff also modifies
`docs/implementation/M01/reports/M01-08.md` — a different, already-closed Story's
report — replacing two references to `docs/implementation/M01/evidence/M01-08-real-swarm-init.txt`

catch a Story that edits *any* Story's report, closed or not. This diff is the
proof that gap is reachable, not hypothetical.

## 5. A weakened test or gate

No test in the committed diff is weakened, skipped, or has an assertion that
cannot fail.

**Finding F-3 (High, on the delivered-but-unapplied patch):** the `bin/gate`
half of the patch implements AC6's "warn without blocking" by calling
`gate_skip "acceptance-mapping" "WARNING: ..."` when
`post_commit_check acceptance-mapping` fails. `gate_skip` records
`result: "skip"` in the gate's JSON report (`bin/_gate_lib.sh:93-98`) — the same
status used for "not selected by --only" and "no frontend file changed", i.e.
*inapplicable*. A real failure (a report the checker cannot parse) becomes
indistinguishable, in the machine-readable output `gate_write_json` archives,
from a check that had nothing to do. Any consumer that filters the JSON for
`result == "fail"` — which is exactly the shape `gate_finish`/CI use to decide
red/green — will silently miss the warning; only the text banner on stdout
carries it, and only in `text` format. This is precisely the "check that cannot
fail (as itself)" pattern the Story asks the reviewer to hunt for (reviewer.md,
item 1), reproduced in the Story's own proposed fix. It should use a status the
report can distinguish from routine skip (e.g. a `warn` result, or `gate_pass`
with the warning text as detail) before the operator applies it. Not blocking
this commit (the code is not live), but it must be fixed before the patch is
applied, or AC6 ships with a weaker signal than AC7 requires of `post-commit`.

Also note the passing branch of that same `if` records nothing at all (no
`gate_run`/`gate_skip`/`gate_pass` call), so `acceptance-mapping` simply never
appears in `bin/gate local`'s report when the mapping is fine — asymmetric with
every other named check, which appears whether it passes or fails. Minor, but
worth folding into the same fix.

## Additional finding

**Finding F-4 (Medium):** `spec/gates/test_evidence_spec.rb` requires
`rails_helper` (line 1), booting the full Rails environment for a spec whose
body is entirely `Open3`/`FileUtils`/`git` against a tmp fixture and needs
neither ActiveRecord nor Rails. Every sibling spec in `spec/gates/` that does the
same kind of fixture-repo work (`gate_scripts_spec.rb`, `fitness_functions_spec.rb`,
`gate_budget_spec.rb`, `lint_rules_spec.rb`) uses the lighter `spec_helper`
instead. Measured: `rails_helper` costs ~2.3s here versus ~0.15s for a sibling
spec using `spec_helper` — small in isolation, but this Story's entire premise is
eliminating avoidable repeated cost in the test/gate pipeline, and its own new
spec adds an avoidable one that the existing convention already avoided.
