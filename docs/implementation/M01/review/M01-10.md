### Critical Findings

**F-1. AC7 not actually implemented — mark_disappeared_nodes_as_down is a stub**

**Location:** `/Users/douglasprado/www/opanel/app/commands/observe_cluster_nodes.rb` lines 145–153

**Evidence:**
```ruby
def mark_disappeared_nodes_as_down
  # This is called after all current nodes have been observed...
  # For now, this is a placeholder; a future Story will implement drift
  # detection and handle node removal (M02-06).
end
```

The method contains only a comment. AC7 requires: "A node that sails from the Swarm vira `DOWN` without being apagado."

The test in `spec/integration/node_observation_spec.rb` lines 1487–1508 does not validate the implementation. It manually calls `node.update!(status: Node::DOWN)` instead of calling `ObserveClusterNodes` to observe a cluster where the node is absent. The test **simulates** the scenario in a comment but does not execute it through the Command. This is a test that asserts implementation without testing it.

**Impact:** AC7 acceptance criterion is satisfied by test assertion only, not by working code. A real observation job will not mark disappeared nodes DOWN because the logic is not there. This is a broken acceptance criterion gate.

**Severity:** CRITICAL (architecture invariant: acceptance criteria must be verified by executed tests, not comments; the test must drive the implementation)

### Medium Findings

**F-4. Fragile staleness derivation — denormalized last_seen_at vs authoritative observed_at**

**Location:** `app/models/node.rb` lines 395–406; `app/queries/nodes_for_cluster.rb` lines 600–602

**Evidence:**
- `last_seen_at` denormalized on Node for UI efficiency (per report line 1153)
- `observation_stale?` checks `last_seen_at` (lines 470–474)
- NodesForCluster reads `last_seen_at` from Node, not NodeObservation.observed_at

If a Job updates a NodeObservation but fails to update Node.last_seen_at, staleness detection will be wrong. The Job in `app/jobs/observe_cluster_nodes_job.rb` calls the Command, and the Command does update last_seen_at (line 127), but the invariant is fragile: no database constraint enforces it.

**Mitigation:** A future Story should add a constraint or trigger to keep last_seen_at in sync.

**Severity:** MEDIUM (maintainability risk; not a bug yet, but fragile design)
