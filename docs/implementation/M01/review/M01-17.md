Based on my review of Story M01-17, I have identified critical issues that block completion. Let me compile my findings.

## Key Findings

**1. CRITICAL: Labels missing project_id — Network creation fails at ownership validation**

In `app/reconcilers/network_reconciler.rb:978`, the reconciler calls:
```ruby
labels: Opanel::Ownership.labels_for(network),
```

But `labels_for` is designed to set `project_id` only for resources that directly respond to `:project_id` or are Services (Ownership.rb:48-52). A Network model has no direct `project_id` attribute, only through its environment relation. Therefore, `labels_for(network)` produces labels missing `project_id`.

However, `Opanel::Ownership.managed_by_platform?` (line 130) requires `[team_id, project_id, environment_id]` to all be present. When the reconciler re-inspects the created network at line 992-994, the ownership check fails:

```ruby
if actual && Opanel::Ownership.managed_by_platform?(actual)
  # ...mark READY
else
  # Stays PROVISIONING, marked FAILED
```

The comment in `SwarmExecutor#network_spec` at line 460 explicitly states: `"# Labels come from the application layer via the payload, computed using Opanel::Ownership.labels_for(environment)."` — it should be environment, not network.

**Evidence:** All 5 tests fail with networks not found or not converging to READY status.

**Impact:** AC1, AC2, AC3, AC4, AC5, AC8, AC11 cannot be satisfied. The reconciler's re-inspection sees `managed_by_platform? = false` and marks the network as FAILED.

**2. HIGH: Test stubs incompatible with actual contract**

**Evidence:** Builder reported "unit tests pass" but the contract changed; the tests still reference the old shape.

**5. MEDIUM: Ownership.technical_name_for excludes Network**

At `lib/opanel/ownership.rb:90-104`, `technical_name_for` raises for anything not Service or Environment. Yet `Network#technical_name` delegates to it. The code works only because the Network model overrides it (line 616-618) to delegate to the environment, but this creates fragile implicit behavior: changing Network's delegation breaks Network naming without affecting Service naming.

---

**6. MEDIUM: Incomplete authorization — Network Policy permits all viewers**

`app/policies/network_policy.rb:731-741` reuses TeamPolicy permissions without Network-specific rules. Networks are derived from Environments, which are derived from Projects, but a viewer with Environment access does not automatically deserve Network visibility. However, NetworkPolicy.view? = decide(:view) returns TeamPolicy permissions, not Environment-scoped checks. This is not a breaking security hole (Environment already gates it), but it defers authorization validation to the Environment, not the Network.

---

**7. MEDIUM: Unused Query**

`app/queries/network_for_environment.rb` is created but never used by any caller in the Story. The application layer creates the network through `EnsureEnvironmentNetwork`, and reconcilers load it via `@environment.network` directly. This query adds surface area without being exercised by the tests.

---

## Summary

All five lab tests fail because `Opanel::Ownership.labels_for(network)` does not include `project_id`. When the reconciler re-inspects after creation, `managed_by_platform?` returns false due to the missing label, and the network is marked FAILED instead of READY. Networks do exist in Swarm (creation is not rejected), but are not recognized as platform-owned.

The ADR-0009 contract is correctly implemented in isolation (RuntimeObservation normalizers, executor changes), but the reconciler passes the wrong resource to `labels_for`.
