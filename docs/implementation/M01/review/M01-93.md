## Finding 1 — Critical: newline in a filename dropped it from the scan

Reproduced as claimed:

- Restored the pre-fix line (`$stdin.read.split(/\0|\n/)`) in a scratch copy of `bin/security`, ran `bundle exec rspec spec/security/security_scan_spec.rb -e "finds a secret in a file whose name contains a newline"`: **red**, `1 example, 1 failure`, with the exact message the report quotes ("a credential in a committable file was skipped because of its name").
- Restored the file exactly (`diff` against the pre-mutation copy: empty) and re-ran the same example: **green**, `1 example, 0 failures`.

Extra variation (own reproduction, not reading the diff): four more name classes planted directly against `bin/security --fast` via `Opanel::Gates::GateRepository.with`, no spec file touched —

- leading dash (`-dash-probe.md`)
- embedded single quote (`quote'probe.md`)
- embedded backslash (`back\slash-probe.md`)
- UTF-8 (`café-segredo.md`)
- a file only in the git index (`git add`ed but not committed)

All five were caught: `secret-scan FAIL`, `leaks found: 1`. `git ls-files -z`/`git ls-files --others --exclude-standard -z` do not quote or escape any of these under `-z`, and the new NUL-only split handles all of them. No further name class found that reopens this gap.

Verdict: **Critical closed.**

## Finding 2 — High: AF-02's whole-file exemption

Reproduced the claimed test behavior first:

- Appended `SOCK = "/var/run/docker.sock"` to `lib/gates/test_evidence.rb` (the reviewer's round-1 plant), ran `bundle exec rspec spec/security/executor_isolation_spec.rb -e "holds no file that reaches the Engine"`: **red**, offender reported as `lib/gates/test_evidence.rb`, matching the report.
- Restored the file (`diff` against the pre-mutation copy: empty), re-ran: **green**.

So the new test does catch the exact reproduction from round 1. But the task asks whether the assertion can be satisfied while a real Docker reference hides in the same exempt file. It can, in two of three variations tried:

- `require "docker"` appended to `lib/gates/test_evidence.rb` — **not caught**, spec stays green (0 failures). `TOUCHES` only matches `/var/run/docker\.sock`, `Docker::\w+`, or the `DOCKER_PROCESS` process-spawn regex; a plain `require "docker"` (the real Ruby Docker client gem) matches none of them.
- `SOCK = "/var/run/" + "docker.sock"` appended — **not caught**, spec stays green. The literal-path regex needs the string unbroken; ordinary string concatenation defeats it.
- A heredoc containing the literal path (`<<~SOCK_DOC` / `/var/run/docker.sock` / `SOCK_DOC`) — **is caught**, spec goes red. This variation does not reopen the gap.

Both bypassing variations were restored exactly afterward (`diff` against the pre-mutation copy: empty in each case).

This matters because the root cause named in round 1 is unchanged: `Af02OnlyExecutorTouchesDocker` still skips the *entire file* once it is in `fitness_self_referential`, not just the lines that justify the exemption. The new spec is a real improvement — it catches the literal reproduction and a plausible constant — but it is a second regex-based gate sitting in front of the same Tier-0 blind spot, and it is evadable by code shapes at least as ordinary as a `require` line or string concatenation, not only by contrived obfuscation. A Tier-0 invariant's compensating test failing on the two most unremarkable ways to write the same reference is a weak compensating control, not a closed finding.

Verdict: **High still open.** The finding is not "AF-02 has no test," it is "AF-02's whole-file exemption is untested against a hidden Docker reference" — and a hidden Docker reference still passes both AF-02 and the new test.
