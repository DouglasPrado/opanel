### Critical Finding: AC9 Not Implemented

**File**: `app/commands/create_environment.rb`

The Story requirement states: "Cluster `DEGRADED` produz warning ou bloqueio conforme policy, com
mensagem explícita."

**What was found**:
- Line 21 defines constant: `CLUSTER_DEGRADED = "The cluster is not ready. Choose a cluster with
  status READY or HOMOLOGATION."`
- **No code path uses this constant** — no validation check exists in the `call` method
- Lines 41–61 validate name, slug, and authorization but **do not validate cluster.status**
- The command allows creation of environments on DEGRADED clusters without any validation or error

**Evidence**:
- Grep search for "DEGRADED" in create_environment.rb returns only the constant definition
- No conditional check for `cluster.degraded?` or `cluster.status == DEGRADED` exists
- Zero test files reference `CLUSTER_DEGRADED` or test this blocking path
- Builder's report lists AC9 as "PENDING (Reconciler at M01-18)" but AC9 is an explicit
  acceptance criterion of M01-11, not deferred

**Impact**: A user can create an Environment pointing to a DEGRADED cluster, violating the Story's
explicit requirement and the architectural principle of never silently creating resources that
cannot execute.
