## 4. `keep_complete_record` / `covered_suites` cross-check

New this round, because the fix's central claim rests on it: I checked
whether `lib/gates/post_commit.rb`'s claim, repeated in the spec's comment and
the Story report ("post-commit refuses to close a Story without a full run at
its commit"), is actually true of `post_commit.rb#tests`, not just asserted.
It is **conditionally** true: `covered_suites` (`lib/gates/post_commit.rb:222`)
returns every suite name only when `metadata["complete"]` is `true`; for a
non-complete run it returns at most one suite type. So `post_commit.rb#tests`
can only clear a Story whose `Required Tests` section names two or more of
`SuiteTypes.names` (`unit, integration, request, policy, contract, security`)
if the last run before that commit was `complete: true`. I checked every
Story's `Required Tests` section under `docs/implementation/M00` and
`docs/implementation/M01` (M01-91's own Required Tests section names four:
`gates, security, budget, integration`) and none names a single suite type
only — every Story in this repository requires ≥2, which makes the claim
true in practice for every `done` Story used as a floor today. It is not a
structural guarantee: a hypothetical future Story naming exactly one suite
type could close without ever producing a fresh complete record, which would
make the floor computed here stricter than intended (an unnecessary `skip`,
not a false `pass` — a fail-safe direction). Noted as Low; not blocking.

## 5. A weakened test or gate — adversarial re-test

### 5a. Suite-ceiling provenance: the freshness bound is real and enforced (fixed), with two narrow, disclosed residual assumptions (Low)

Reproduced all three negative paths against a backed-up copy of
`tmp/test-results/rspec-metadata-complete.json`, restored byte-for-byte after
(`diff` against the backup showed no difference):

| Mutation | Result |
|---|---|
| `commit` set to this repo's root commit (`219e16c...`) | `1 pending` — `"the kept record (219e16ce497e) predates the last closed Story (07a4cf8) — run bin/test"` |
| `commit` set to `""` | `1 pending` — `"the kept record names no commit — run bin/test"` |
| `commit` set to an unrelated 40-hex value not in this history | `1 pending` — `"the kept record is from outside this history (deadbeefdead) — run bin/test"` |
| restored | `1 example, 0 failures` |

This closes round 3's point 1 (no recency bound at all): the floor is now a
real commit (`07a4cf8`, independently recomputed by hand from every `done`
Story's commit across every milestone's `tasks.json`, taking the one with the
highest `git rev-list --count`, which matches what the code selects). Round
3's point 2 (uncommitted changes since the last full run are invisible to a
commit-keyed check) is not closed and the comment now says so honestly
instead of claiming otherwise — "a suite cannot read its own duration, so this
example is one full run behind by construction" — and the tree/working-tree
pair is observability in the failure message, not an enforced bound. That is
an accurate, narrowed claim rather than the round-3 overclaim, so I do not
re-raise it.

Two assumptions the fix relies on, both currently sound but worth naming:

1. `last_closed_story_commit` picks the "newest" `done` Story commit by
   `git rev-list --count`, a topological proxy that is only reliable under a
   linear history (no merge commits). Verified `git log --merges --oneline`
   returns 0 commits on this branch's full history (107 commits), and this
   project's own git discipline (`AGENT_RULES.md`, "1 Story ≈ 1 coherent unit
   of commit") makes a linear history the expected shape. Sound today; would
   silently misrank two Stories closed on since-merged parallel branches.
   Low, not exercised.
2. When no Story has ever closed, `floor` is `nil` and the bound degrades to
   ancestry-only (round 3's "no real bound"), which the comment discloses
   ("Nil when no Story has closed yet") but does not guard against. Currently
   unreachable in this repository (18 `done` Stories already exist in M00
   alone). Low, not exercised, self-resolving.

Neither weakens the fix's effect on the finding it was written to close; both
are edge cases the fix does not claim to cover and the comment does not
misstate.

### 5c. New: `DIFF_SCAN_CEILING_MS` is declared and never checked (Medium)

```ruby

DIFF_SCAN_CEILING_MS = 60_000
```

is new in this round's diff. `grep -n "DIFF_SCAN_CEILING_MS"` across
`spec/gates/gate_budget_spec.rb` and `spec/security/security_scan_spec.rb`
finds only the declaration — no example reads it. The file's own header

found, not how long the scan took. This is not a false-green risk today
(nothing reads the constant to produce a passing assertion off it), so it is
not High, but it is a documented claim the diff does not back with a test —
exactly the category the Story's own AC7 and Required Tests ("budget") ask
for, and it sits in the file this round's fix touched. Medium.
