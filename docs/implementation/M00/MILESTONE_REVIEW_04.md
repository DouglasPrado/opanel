What blocks acceptance is not work; it is the state of the commit being handed over.

**The pipeline is red at the reviewed commit.** The only CI run at `31a2cae` — run `34260997722`, a `push` to `main` — concludes `failure`: `security-fast` fails on `spec/security/security_scan_spec.rb:129` ("secret scan passes on this repository, tree and history"), and `pr-gate` fails with it. The Exit Gate in `docs/implementation/M00/README.md:145` requires "o pipeline de CI está verde em uma execução completa do branch". At HEAD it is not.

**The cause is a private key that this Milestone's own negative testing committed and merged.** The run's archived evidence (`evidence-security-fast-34260997722-1` → `security/scanners/gitleaks-history.json`) contains exactly one finding: rule `private-key`, file `config/ci_negative_key.pem`, commit `f797866c`. None of this appears anywhere in the Implementation Pack; the pack's last word on the subject is `FIX_REPORT_03.md:219`, "The five negative pull requests are not delivered."

**Nothing enforces the gates.** `gh api repos/DouglasPrado/opanel/branches/main/protection` returns `404 Branch not protected`. `pr-gate` is described in `.github/workflows/ci.yml:183-185` as "the check branch protection requires"; it is required by nothing. `merge-gate` has never concluded `success`.
