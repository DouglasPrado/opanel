## Schema / API / Events

`GET /up` — the readiness contract: `{status, checks: {application, database, queue}}`.
No version, hostname, connection string or resource count.

## Decisões locais

- **The correlation id is established by a middleware after
  `ActionDispatch::RequestId`, not by a controller callback.** Rails logs
  "Started GET" and "Completed 200" from outside the controller, and an exception
  handled by the middleware stack never reaches one — those are the lines an
  operator reads first, so the correlation has to exist before them. An earlier
  attempt anchored to `ActionDispatch::Executor` and saw a nil request id, because
  the Executor runs *before* RequestId.
- **The reserved fields of Annex I §19.2 are part of the contract now** —
  `operation_id`, the tenancy chain, `actor_id`. They appear when set and are
  omitted when not, so nothing about the formatter changes when M01 starts
  setting them. A test fills all eight to prove it.
- **Redaction runs at the sink.** The discipline of not logging a secret fails
  eventually: a driver interpolates a connection string into an exception, a
  middleware dumps a header. Fields whose name means "secret" are masked whatever
  they hold; credential shapes are masked wherever they appear.
- **The formatter falls back twice and always emits a line.** A formatter that
  raises takes the request with it and loses the message it was about to explain.
- **`/up` reports the three separately** because they fail separately and an
  operator responds to each differently. A degraded dependency answers 503 with a
  classified cause — never a generic timeout, and never a claim of health while
  something it needs is unreachable.
