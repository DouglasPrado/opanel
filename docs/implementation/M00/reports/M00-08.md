## Decisões locais

- **A console error fails a component test.** React and Radix report broken
  accessibility trees, invalid props and bad hook usage there; a suite that filters
  them is not checking what it claims to. The one exception, `not wrapped in act(`,
  is documented at the filter.
- **The universal states are a shared contract, not two copies of a convention.**
  `spec/frontend/support/universal-states.ts` defines the test id, the role and the
  *rule* for each of the eight states, and the failure message quotes the rule.
- **The examples render the imported library**, not components written for the
  test. That is what makes them the pattern every following UI Story copies.
- **The gallery's accessibility debt is a baseline that can only shrink.** A new
  violation fails; a baselined one that disappears also fails, so the entry gets
  removed. Opanel's own pages carry no baseline — `e2e/smoke.spec.ts` fails on any
  violation at all.
- **Redaction masks text and deletes what it cannot mask.** A trace archive cannot
  be rewritten in place; losing a diagnostic is recoverable, publishing a
  credential is not. The teardown scans the recordings, not Playwright's own
  bundled viewer, whose minified code produced only false positives.
- **The E2E server renders errors the way production does**, behind
  `OPANEL_RENDER_ERROR_PAGES`. A journey asserts what a user sees, and a user sees
  the Inertia error page, not Rails' developer page.
- **One retry, and a reporter that says why it happened.** Retrying until green is
  what Annex D §20.1 forbids; the classifier exists so the flaky rate distinguishes
  an environment that was not ready from an assertion that failed.

## Dependências novas

| Package | Version | Why | Alternatives |
|---|---|---|---|
| `vitest` | 5.0.0 | Component test runner (SC-03). Shares Vite's transform, so tests and bundle resolve identically. | Jest, which would need a second transform pipeline. |
| `jsdom` | latest | DOM for component tests. | happy-dom, less complete for Radix. |
| `@testing-library/react`, `/user-event`, `/jest-dom` | latest | Role- and text-based queries — the selector policy of Annex D §11.1 in library form. | Enzyme-style rendering, which encourages the fragile selectors the policy bans. |
| `@playwright/test` | latest | Browser journeys (SC-03), with trace, video and a managed web server. | Cypress, which has no equivalent trace artifact. |
| `@axe-core/playwright` | latest | WCAG 2.2 AA in the browser. | Static lint alone, which cannot judge contrast or focus order. |

All MIT, development-only, pinned in `package-lock.json`. Chromium is installed
with `npx playwright install chromium`; `bin/test:e2e` fails with that instruction
rather than timing out when it is missing.

## Pendências / conflitos

- **Two defects found and fixed, both invisible to server-side tests.**
  1. `inertia_rails` emitted the v2 `data-page` attribute while `@inertiajs/react`
     3.7 reads a `<script type="application/json">` element. React never mounted.
     Every request spec passed because the payload was present — just not where the
     client looks. Fixed with `config.use_script_element_for_initial_page = true`,
     and the four specs that parsed the attribute by hand now share
     `spec/support/inertia.rb`.
  2. The panel's CSP blocked the component library's inline styles. Radix positions
     popovers, tooltips, scroll areas and progress bars by writing to
     `element.style`, which no nonce can authorize. `style-src` now allows
     `unsafe-inline`; `script-src` stays strict. The trade-off is recorded in the
     initializer.
- **Three accessibility violations remain, upstream**, recorded in
  `e2e/accessibility-baseline.json` — see M00-05's report.
- Only Chromium is configured. Cross-browser coverage is not an M00 requirement and
  belongs with the hardening work in M13.
- The E2E suite is not yet in a merge gate; M00-11 wires it in.
