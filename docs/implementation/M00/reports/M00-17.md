## Decisões locais

- **The lab is identified by a property of the daemon, not by configuration.**
  `bin/swarm-lab up` applies the node label `opanel.lab=true`, and every mutation
  asserts it first. The autonomous workspace must never reach a real cluster
  (Annex H §12.2), and a check an environment variable can disable is not a check
  — a spec asserts no `SKIP_`/`FORCE_`/`ALLOW_` escape hatch exists.
- **Cleanup is idempotent by construction.** A crashed example leaves resources
  behind and the *next* run has to cope with that; a harness that only cleans up
  on the happy path poisons every run after the first failure. Resources carry the
  run's pid, so a leak names what made it.
- **The lab image is configurable and must be present locally.** The harness
  deliberately does not depend on registry access at test time. When the image is
  missing the `:swarm` examples are skipped with instructions — never reported as
  passing.
- **`lib/gates/swarm_lab.rb`, `bin/swarm-lab` and `spec/support/swarm_lab` are
  registered in `docker_boundaries`.** AF-02 would otherwise report the harness
  for being about Docker.

## Dependências novas

`none`. The harness shells out to the `docker` CLI rather than adding a client
gem: the executor of M01 will need a typed, allowlisted boundary of its own, and
a gem chosen now would be chosen for the wrong problem.

## Pendências / conflitos

`docker pull` was unreachable from this environment during implementation, which
is why the lab image is configurable. AC1–AC9 were proven with a locally present
image (`postgres:17-alpine`); CI pulls the configured default. The two paths —
image present and image absent — are both exercised above.
