## Decisões locais

- **A Story declares its boundary before editing.** Written afterwards, a
  boundary only describes what happened. An undeclared Story **fails** rather than
  passes — a check satisfied by declaring nothing reports green over exactly the
  scope creep it exists to catch. This Story's own widening is recorded in
  `boundaries.yml` with its reason.
- **Bypass detection is evidence, not a flag.** `--no-verify` leaves no trace in a
  commit; what it leaves is the absence of one. The hook records the tree it
  checked, and post-commit reports any commit whose tree no hook ever saw.
- **`--no-verify` is checked against what *runs*.** Scoped to scripts, hooks,
  workflows and config. Prose that names the flag in order to forbid it is not a
  use of it, and a checker that cannot tell the difference makes the rule
  unwritable.
- **Speed was bought by narrowing scope, never by dropping a check.** First
  measurement 13 s — bypass territory. `gitleaks git --staged` asks exactly the
  pre-commit question (9.2 s → 0.2 s); `--fast` skips the `:slow` gate suites,
  which run other gates against planted failures. CI still scans the whole tree,
  the history, and runs every suite.

## Pendências / conflitos

Commits made before this Story existed have no pre-commit record, so
`bin/gate post-commit` reports them as unverified. That is accurate rather than a
defect: the gate can only speak for commits made after the hook was installed.

**Corrected at fix attempt 03**, from that round's repair of the CI pipeline. The
AC4 example "is what git is configured to run" ran `bin/install-hooks --check`
against the working checkout and required it to pass. On a developer machine it
did, because `bin/setup` had run; on a CI runner nobody had run it, and the example
failed the `unit` job. What it asserted was the ambient state of whichever machine
happened to run it — that somebody once ran the script — rather than a property of
the code. It now proves the round trip in a scratch repository reached through
`GIT_DIR`/`GIT_WORK_TREE`: `--check` refuses a repository that is not configured,
`bin/install-hooks` configures it, and `--check` then agrees. Two assertions where
there was one, and it never touches the hooks of the checkout it runs in — an
example that unset them and then died would silently disable the gate it tests.
