## Decisões locais

- **The workspace guardrail runs before anything is installed or connected.** If
  this machine holds a production credential, nothing else should run on it — and
  checking after `bundle install` has already run means checking after the machine
  has already been used.
- **`bin/dev` is written here rather than delegated to foreman**, for the one
  behaviour that matters: when a process dies it says *which* and stops the
  others. A supervisor that leaves the web server up while the worker is silently
  dead is how an afternoon disappears. An occupied port names the process holding
  it, because "address already in use" does not.
- **The queue health check rescues `ActiveRecord::ActiveRecordError`, not
  `StandardError`.** Reporting a `NoMethodError` in our own code as "the queue is
  unavailable" sends an operator to look at the wrong system. The custom cop from
  M00-09 caught this; the fix was to narrow the rescue rather than to weaken the
  cop.
- **Development needs `script-src 'unsafe-inline'`** for the React Refresh
  preamble. Scoped to development, with a spec asserting test and production keep
  `script-src 'self'` — which is the directive an XSS actually needs.

## Pendências / conflitos

The clean-clone verification is the only thing that found the two development
defects (missing `vite_react_refresh_tag`, IPv6-only Vite). Neither the HMR check
of M00-04 nor the E2E of M00-08 could have: the first only proved the dev server
re-transformed a module, and the second runs against a built bundle. Worth
repeating before any Milestone that changes the asset pipeline.

`bin/dev`'s supervision is asserted by reading the script, not by killing a child
of a running supervisor. The two properties that matter — that a dead child stops
the others, and that its name reaches the output — are both visible in the source
and both asserted; what is not covered is the process actually doing it. Carried
as a known gap rather than described as a runtime test.
