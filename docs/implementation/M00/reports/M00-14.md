## Schema / API / Events

`config/pack/tasks.schema.json` — versioned so an editor and a reviewer read the
same contract. `bin/stop-gate` emits `{ok, milestone, reason, checks[]}`.

## Decisões locais

- **Validated by hand rather than by a JSON Schema library.** The schema stays
  authoritative for editors; the rules that matter — a `file` that exists, a
  cycle, a `done` with no commit — are ones no schema expresses, so a dependency
  would buy the easy half and leave the hard half.
- **No Stop Gate check is satisfiable by assertion.** An agent asked whether its
  work is finished will say yes; the failure mode of a loop is optimism, not
  malice, and a gate made of assertions inherits it.
- **Annex H §4.2's "story acceptance script" has no equivalent here**, and
  inventing one the agent writes would be a check the agent grades. What is
  verifiable instead: every required Story done, each with a report that maps its
  criteria to something.
- **`ok:false` exits 0 in JSON mode.** It is the answer, not a crash — the caller
  reads the field. Text mode exits non-zero so a shell `&&` behaves.
- **Checks are ordered cheapest-first**, so a run that is going to fail usually
  fails in seconds rather than after the whole suite.
- **`bin/pack next` returns to work already underway before starting anything
  new.** Otherwise a loop ends up with six half-built Stories and no checkpoint.
