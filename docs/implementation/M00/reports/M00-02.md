## Schema / API / Events

- Schema: `infrastructure_checkpoints (id bigserial, name text NOT NULL, counter bigint NOT NULL DEFAULT 0, timestamps)`, unique index on `name`, check constraint `counter >= 0`. Reversible; verified by `db:rollback` and re-`db:migrate`.
- API: `none`.
- Events: `none`.

## Decisões locais

- **`infrastructure_checkpoints` keeps a bigint primary key.** ADR-0002 governs
  domain entities exposed through the API, MCP and Swarm labels; this table is
  neither. See Pendências.
- **`ci` is a real Rails environment, not `test` with a different database name.**
  AC6 names three environments, and forcing eager loading in CI catches
  autoload errors that development's laziness hides. `config/environments/ci.rb`
  loads `test.rb` and overrides the two settings that must differ.
- **The Migration Gate reads source text, not a booted migration.** It has to run
  in the Pre-commit Gate before any database exists, and it must name the file,
  the line and the rule rather than raise from inside Active Record.
- **Markers are the only escape hatch,** and each forces a written reason into the
  file: `# migration-phase:`, `# migration-contract-ref:`, `# migration-forward-fix:`,
  `# migration-index-review:`.
- **`Opanel::DatabaseConnection.check` rescues `StandardError` broadly.** It never
  returns success on failure — it returns a `Result` that is not `available?` with
  a classified cause — which is the opposite of the generic rescue Annex I §7.1
  forbids.
- **`lib/gates/` is excluded from Zeitwerk** so the checkers can be required
  directly by `bin/` scripts and specs without booting Rails.

## Acceptance Criteria

- [x] 1. `db:prepare` creates the schema from an empty database — the three
      databases were dropped and `db:prepare` exited `0`.
- [x] 2. The example migration applies with `db:migrate` and reverts with
      `db:rollback` without structural loss — rollback removed the constraint, the
      index and the table; re-migrating restored all three.
- [ ] 3. **Deferred.** The identifier helper is not implemented: ADR-0002 is
      `Proposed`. This is the Story's own precondition, not an omission.
- [x] 4. The Migration Gate rejects a column removal without a contract-phase
      marker — `CONTRACT_PHASE` violation, exit `1`; specs
      `spec/gates/migration_gate_spec.rb` cover the missing marker, the marker
      without a decision reference, the compliant form, and destructive SQL hidden
      inside `execute`.
- [x] 5. The Migration Gate rejects a migration with neither `down` nor a
      documented forward-fix — `REVERSIBILITY` violation, exit `1`; specs also
      cover `execute` inside `change`, `reversible do`, and `remove_column`
      without a type.
- [x] 6. `development`, `test` and `ci` use distinct, configurable databases —
      asserted in `spec/security/database_configuration_spec.rb` and
      `spec/integration/database_spec.rb`; each name comes from its own
      environment variable.
- [x] 7. An integration test runs against real PostgreSQL —
      `spec/integration/database_spec.rb` asserts `adapter_name == "PostgreSQL"`
      and exercises the unique index, the check constraint and a transaction
      rollback in the database.

## Pendências / conflitos

- **AC3 deferred — SC-08 / ADR-0002 is `Proposed`.** The Story's Preconditions say
  so explicitly: implement everything except the ID helper and record the point as
  pending. `infrastructure_checkpoints` is a technical table, not exposed and not a
  domain entity, so a bigint key is correct either way. The first domain table
  (`M01-01`) is blocked until a human accepts the ADR. **No specification conflict
  was created and none was resolved silently.**
- Booting a non-`development`/`test` environment requires `SECRET_KEY_BASE`, as
  observed on the `ci` environment. Rails fails closed with an actionable message,
  which is the desired behaviour; M00-16 turns it into a typed required key with a
  message that points at the environment rather than at `credentials:edit`. This is
  the pendency M00-01's review recorded as F-2.
- `db/seeds.rb` is still the generator default. Development seeds belong to M00-06.
