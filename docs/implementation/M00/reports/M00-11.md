## Schema / API / Events

`config/ci/jobs.yml` is a contract: job names are required by name by the Merge
Gate, so renaming one is a pipeline change needing its own Story or ADR.

## Decisões locais

- **The workflows schedule; they define nothing.** A pipeline whose definition
  lives only inside a CI provider can be tested only by pushing, which means it is
  not tested. Everything CI runs is reproducible locally by name.
- **The Merge Gate runs on the pull request, not on push to `main`.** It decides
  whether a merge is *allowed*; after the push there is nothing left to gate.
- **CI green is checked by job name.** Not "most checks passed", not "nothing
  red". A job that vanished from the run fails the gate, so an agent cannot
  unblock a merge by deleting the job that was failing.
- **What cannot be verified fails closed.** Required approvals live in branch
  protection; without `gh` the gate says it could not check them and exits
  non-zero. Missing evidence is never read as consent.
- **`rollback-known` asks the Migration Gate rather than restating its rule.** The
  first version demanded a `migration-forward-fix:` marker unconditionally, which
  would have forced a meaningless marker onto every reversible migration — a
  second, stricter copy of a rule that already exists.
- **Empty slots report `empty`.** A job that says green while running nothing is a
  false statement about the build, and worse than a missing check because nobody
  goes looking for it.
- **One workflow rather than two.** The Merge Gate has to read the result of every
  required job, and cross-workflow artifacts are a plumbing problem rather than a
  quality one. The stage distinction stays in `jobs.yml` and in one `if:`.

## Dependências novas

`rexml` (`:development, :test`) — `bin/flaky-rate` reads the JUnit output back,
which needs the per-test outcomes only the XML carries. Ruby's own XML parser,
pure Ruby, no native extension; stdlib until Ruby 3.0 and a bundled gem since, so
the line is the unbundling catching up rather than a new dependency in any real
sense. Alternatives: hand-rolled parsing (fragile against a format we do not
own) and nokogiri (present transitively, but depending on a transitive gem
directly is how a dependency disappears under you). BSD-2-Clause licensed and
pinned in `Gemfile.lock`.
