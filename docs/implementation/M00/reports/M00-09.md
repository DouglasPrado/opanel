## Decisões locais

- **Two custom cops rather than configuration.** Annex I §7.1 states two rules no
  stock cop expresses: a broad rescue must not answer success, and an error's
  class is what retry, status and the client response branch on. Writing them as
  cops makes them executable instead of advisory.
- **`SilentRescue` fires on a truthy literal return, not on any broad rescue.**
  Broad rescues are legitimate — `Opanel::DatabaseConnection.check` uses one to
  classify a failure. What is never legitimate is answering `true`.
- **The Suppression Gate is separate from the linters.** It is the only thing
  standing between the ruleset and slow decay by `# rubocop:disable`, and it has to
  cover every checker at once, including Brakeman and `@ts-expect-error`.
- **Prettier adopts the imported library's configuration** and is scoped to the
  frontend. Reformatting 169 vendored files would be drift; reformatting the
  specification would be a diff no reviewer could read.
- **TypeScript pinned to 6.x, ESLint to 9.x.** `typescript-eslint` supports
  neither TypeScript 7 nor ESLint 10, and `eslint-plugin-jsx-a11y` stops at ESLint
  9. Taking the newest of each requires `--legacy-peer-deps`, which resolves a tree
  nobody has tested. The pins are one major behind the frontier and fully
  supported.
- **`bin/typecheck` has no incremental mode.** TypeScript resolves the whole
  program to answer anything about one file; a flag that pretended otherwise would
  be dishonest. It is inside the budget as it stands.

## Acceptance Criteria

- [x] 1. `bin/lint` runs RuboCop and the TypeScript linter and exits `0` clean.
- [x] 2. `bin/format` normalizes Ruby and TypeScript idempotently — two consecutive
      runs produce an identical diff.
- [x] 3. `bin/typecheck` runs `tsc --noEmit` without error.
- [x] 4. An incremental mode exists and touches only changed files — `--changed`,
      measured at 1.2 s on a 20-file diff against 2.4 s for the repository.
- [x] 5. The import boundary rejects a server-only import inside `app/frontend/` —
      proven for a Node built-in and for a Rails-tree import, and shown to accept
      an in-tree import.
- [x] 6. The generic-rescue-returning-success rule rejects a planted violation —
      `Opanel/SilentRescue`, proven for `rescue StandardError; true` and for a bare
      `rescue` returning `:ok`, and shown to accept a re-raise and a classified
      failure.
- [x] 7. The CSS-class selector rule rejects a planted violation — proven for
      `locator('.class')`, `querySelector('.class')` and `getElementsByClassName`,
      and shown to accept `getByRole` and `getByTestId`.
- [x] 8. A suppression without justification is rejected — proven for
      `rubocop:disable` and `eslint-disable-next-line`, and shown to accept a
      reference on the same line and on the line above.
- [x] 9. The suppression document exists and the lint error points at it — the
      Suppression Gate's remedy names `docs/engineering/lint-suppressions.md`, and
      a test asserts both the message and the file.

## Dependências novas

### Dependency: `rubocop-rails-omakase` `1.1.0`

- **Story:** `M00-09` · **Ecosystem:** rubygems
- **Problema resolvido:** the Ruby style baseline.
- **Alternativas avaliadas:** a hand-written `.rubocop.yml`.
- **Por que não bastam:** Omakase is the Rails default; writing an equivalent from
  scratch is work with no upside. `.rubocop.yml` specializes it and does not relax
  it.
- **Maintenance/Security/License:** maintained by the Rails core team; MIT;
  development group only.
- **Impacto de longo prazo:** médio. **Lockfile:** `Gemfile.lock`.

## Pendências / conflitos

- **No specification conflict found.**
- TypeScript is one major behind the latest release on purpose. Moving to 7.x is a
  one-line change once `typescript-eslint` supports it, and is worth revisiting
  before M01 closes.
- Two corrections landed with M00-08 because that Story's files exposed them: the
  Suppression Gate was reporting its own source, its spec and its documentation
  (all three contain the patterns by definition), and Prettier's scope did not
  reach `e2e/` or `spec/frontend/`. Both are in `97eabb3`.
- Brakeman and the dependency scanners are M00-10; `bin/security` does not exist
  yet, so `bin/lint` covers style and boundaries only.
