## Findings

### F-1 — Five functions pass vacuously

- **Dimensão:** Correção
- **Severidade:** Low
- **Evidência:** AF-01, AF-03, AF-04, AF-05 and AF-10 have no subject yet — there
  is no MCP adapter, no reconciler, no serializer.
- **Ação:** deliberate and necessary. The checker has to exist before the code it
  governs, so the first file to cross a boundary is caught by the build rather
  than by a reviewer who happened to notice. Because a vacuous pass is
  indistinguishable from a broken rule, each of the five is proven against a
  planted fixture, so it is known to work before it has anything real to check.

### F-2 — AF-02 needed a self-reference exclusion

- **Dimensão:** Arquitetura / Segurança
- **Severidade:** Medium (resolved)
- **Evidência:** the checkers contain Docker patterns *because they are the
  checkers*, and AF-02 reported them.
- **Ação:** a separate `fitness_self_referential` list, kept apart from
  `docker_boundaries` on purpose. The latter grants the Tier-0 privilege and
  widening it needs an ADR; the former only says "these files talk about Docker,
  they do not talk to it". Merging them would have quietly granted socket access
  to a checker.

### F-3 — Comments must never trigger a rule

- **Dimensão:** Operação
- **Severidade:** Low
- **Evidência:** every checker strips comments before matching.
- **Ação:** deliberate. A function that fires on the line explaining it is a
  function people learn to work around, and a checker people work around protects
  nothing.
