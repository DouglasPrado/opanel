## Findings

### F-1 — Two custom RuboCop cops are project-maintained code

- **Dimensão:** Simplicidade
- **Severidade:** Low
- **Evidência:** `lib/rubocop/cop/opanel/{silent_rescue,unclassified_error}.rb`.
- **Ação:** justified by there being no stock equivalent. `Lint/SuppressedException`
  catches an empty rescue but not one that answers `true`, and nothing ships a rule
  about raising a bare string. Both cops are small, both are covered by four
  examples each, and `SilentRescue` deliberately fires only on a truthy literal
  return so it does not condemn the legitimate broad rescue that classifies a
  failure. If they produce false positives in practice, the rule is the defect and
  it gets its own Story.
- **Estado:** closed

### F-2 — The Suppression Gate excludes its own source and spec

- **Dimensão:** Segurança / Correção
- **Severidade:** Low
- **Evidência:** `bin/suppression-gate` — `SELF_REFERENTIAL`.
- **Ação:** unavoidable and narrow. The gate's source contains the patterns as
  regular expressions and its spec contains them as planted violations; scanning
  them reports the checker for being a checker. Markdown is skipped for the same
  reason — an example in prose suppresses nothing. The list is two entries and
  adding to it is editing a gate, which the Post-commit Gate flags (M00-12) and
  which needs its own Story (Annex I §21.2). The residual risk is a real
  suppression hidden inside those two files, which review covers.
- **Estado:** closed

### F-3 — Six ESLint rules are off for the imported component tree

- **Dimensão:** Correção
- **Severidade:** Medium
- **Evidência:** `eslint.config.js`, the block whose `files` list is exactly the
  M00-05 import.
- **Ação:** the alternative is editing vendored source, which M00-05 forbids and
  which nobody would reconcile upstream. Three of the six are accessibility rules,
  and they are the ones worth noting: they are not waived, because the runtime axe
  check over rendered output (M00-08) is what actually decides WCAG 2.2 AA, and it
  is stricter than a static rule. The block is scoped by an explicit file list
  rather than a glob over `app/frontend`, so Opanel's own code cannot drift into
  it silently.
- **Estado:** open, resolved by fixing the library upstream.

### F-4 — TypeScript was downgraded from 7.0.2 to 6.0.3

- **Dimensão:** Dados / Operação
- **Severidade:** Low
- **Evidência:** `package.json`.
- **Ação:** `typescript-eslint` declares `typescript@>=4.8.4 <6.1.0`, and no
  published version supports 7. The choice was between a supported toolchain on
  TypeScript 6 and `--legacy-peer-deps` on a combination the linter has never been
  tested against. Nothing in the codebase uses a 7-only feature — the typecheck
  passes identically. Recorded as a pendency to revisit before M01 closes.
- **Estado:** open, revisit when `typescript-eslint` supports TypeScript 7.
