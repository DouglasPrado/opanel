## Findings

### F-1 — 52 of 84 upstream components were imported

- **Dimensão:** Escopo
- **Severidade:** Medium
- **Evidência:** `INVENTORY.md`, section *Available upstream, not imported*.
- **Ação:** deliberate, and the alternative is worse in both directions. Importing
  all 84 would add `zod`, `cmdk`, `vaul`, `sonner`, `recharts`, `embla`,
  `date-fns`, `@dnd-kit/*`, `@headless-tree/*`, `@base-ui/react`,
  `react-resizable-panels`, `input-otp` and `@shadcn/react` — thirteen packages
  with no caller, which the Milestone explicitly forbids ("não instalar
  dependência para usar depois") and which the Dependency Gate's proportionality
  criterion rejects. Several of them exist only for Brazilian document and payment
  inputs a PaaS control plane does not handle.
  Importing none would leave the Reuse Gate with nothing to check.
  The middle is honest **because the inventory names what was left behind and what
  it costs**: "does an equivalent exist?" still answers yes, importing one is a
  copy plus a Dependency Justification, and rebuilding one is a review finding.
  The residual risk is a Story that does not read the second table and builds a
  toast from scratch; the inventory puts that table above the fold and the Reuse
  Gate step 2 points at it.
- **Estado:** closed — recorded rather than hidden.

### F-2 — Two TypeScript strictness flags were dropped for the whole project

- **Dimensão:** Correção
- **Severidade:** Medium
- **Evidência:** `tsconfig.json` — `exactOptionalPropertyTypes` and
  `noUncheckedIndexedAccess` removed; they produced 6 errors, all inside imported
  components.
- **Ação:** the flags are lost for Opanel's own code too, which is a real cost.
  The alternatives were worse: editing six vendored files is drift from upstream
  that nobody would reconcile, and TypeScript cannot apply different options to
  part of one program without splitting it into referenced projects with
  declaration emit — a build change out of proportion to the benefit. `strict`
  itself is on, which is the flag that carries most of the value, and the
  reasoning plus the path back is written into the config. Re-enabling means
  fixing the library upstream.
- **Estado:** open, owned by the design system; re-enable when upstream allows.

### F-3 — Three WCAG 2.2 AA violations remain, baselined

- **Dimensão:** Correção / Segurança (accessibility)
- **Severidade:** Medium
- **Evidência:** `e2e/accessibility-baseline.json`; `color-contrast` on 9 nodes,
  `aria-input-field-name` on 1, `scrollable-region-focusable` on 1.
- **Ação:** all three are upstream and unreachable from here — a palette below
  4.5:1, a Slider that does not forward a label to its thumb, and a ScrollArea
  that does not forward props to its Viewport. The baseline is not a waiver: it is
  a list that can only shrink, enforced in both directions, with a named owner and
  a concrete fix per entry. Opanel's own pages carry no baseline at all — the
  smoke journey fails on any violation. Everything that *was* fixable here was
  fixed: six missing accessible names in the gallery demos, found by the same
  check.
- **Estado:** open, owned by the `gba.dev` design system.

### F-4 — The gallery registry is one 800-line file

- **Dimensão:** Simplicidade
- **Severidade:** Low
- **Evidência:** `app/frontend/components/features/gallery/registry.tsx`.
- **Ação:** accepted. It is a flat list of 52 independent literals with no logic;
  splitting it into 52 files would add navigation cost without reducing
  complexity, and the consistency test reads it as one array. If it grows a second
  responsibility, it splits then.
- **Estado:** closed
