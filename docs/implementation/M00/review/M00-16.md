## Findings

### F-1 — Configuration is validated before Rails initializes, outside Zeitwerk

- **Dimensão:** Arquitetura
- **Severidade:** Low
- **Evidência:** `config/application.rb` `require_relative`s
  `lib/opanel/configuration.rb`, which is excluded from `autoload_lib`.
- **Ação:** deliberate. An initializer runs after Zeitwerk and after other
  initializers have already read configuration, which is too late to say "do not
  start". The cost is one file that is required rather than autoloaded, and it is
  named in both the ignore list and the requiring comment. The first attempt used
  an initializer and failed with `uninitialized constant Opanel::Configuration`,
  which is what made the ordering explicit.
- **Estado:** closed

### F-2 — The guardrail matches shapes, so it can be evaded and can misfire

- **Dimensão:** Segurança
- **Severidade:** Medium
- **Evidência:** `lib/gates/workspace_guardrail.rb` — regular expressions over
  environment values and a fixed list of files.
- **Ação:** a real limit, stated rather than hidden. A credential with no
  recognisable shape, in a file outside `SCANNED_FILES`, passes. The guardrail is
  a guard against accident — a copied `.env`, an exported `AWS_ACCESS_KEY_ID`, a
  `DOCKER_HOST` left pointing at a cluster — not against an adversary who already
  has the workspace. It is one layer: the secret scan over the tree and the branch
  history (M00-10) is another, and `bin/stop-gate` (M00-14) runs this one again
  before a Milestone can close.
  The false-positive direction is the one that would make it useless, because a
  guardrail people learn to ignore protects nothing. Six examples pin what it must
  *not* flag: a local connection URL, a Unix-socket Docker host,
  `RAILS_ENV=production`, `REPRODUCIBLE_BUILD`, an empty variable, and an ordinary
  development environment.
- **Estado:** closed — accepted limitation, layered rather than relied on alone.

### F-3 — `LOCAL_HOSTS` treats `db` and `postgres` as local

- **Dimensão:** Segurança
- **Severidade:** Low
- **Evidência:** `LOCAL_HOSTS` includes the hostnames a compose network uses.
- **Ação:** intentional. A developer running PostgreSQL in compose reaches it at
  `db` or `postgres`, and flagging that would produce a false positive on every
  run — the failure mode F-2 describes. The residual risk is a production host
  literally named `db`, which would be an unusual thing to point an autonomous
  workspace at and which the `PRODUCTION_NAME` and shape rules would still catch
  if the credential looked like one.
- **Estado:** closed
