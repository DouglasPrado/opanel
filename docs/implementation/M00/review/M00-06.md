## Findings

### F-1 — The clean clone found two defects the existing suites could not

- **Dimensão:** Correção
- **Severidade:** High (resolved in this Story)
- **Evidência:** the layout was missing `vite_react_refresh_tag`, so
  `@vitejs/plugin-react` could not find its preamble and every module failed to
  evaluate — the page loaded, React never mounted, the server log said nothing.
  Vite also bound IPv6-first, so a browser resolving `localhost` to `127.0.0.1`
  found nothing listening.
- **Ação:** both fixed. Worth recording *why* they survived: M00-04's HMR check
  only proved the dev server re-transformed a module, and M00-08's E2E runs
  against a built bundle. Neither exercises development-mode module evaluation in
  a real browser. The clean-clone drive should be repeated before any Milestone
  that changes the asset pipeline.

### F-2 — Development relaxes `script-src`

- **Dimensão:** Segurança
- **Severidade:** Low
- **Evidência:** `config/initializers/content_security_policy.rb` adds
  `:unsafe_inline` and `:unsafe_eval` to `script_src` in development.
- **Ação:** accepted, scoped, and fenced. The React Refresh preamble is inline;
  without it development does not run. A spec asserts test and production keep
  `script-src 'self'`, which is the directive an XSS actually needs. The
  relaxation cannot leak into another environment without that spec going red.

### F-3 — The health check's rescue was too broad

- **Dimensão:** Testes / Observabilidade
- **Severidade:** Medium (resolved)
- **Evidência:** `HealthController#queue_check` rescued `StandardError`, so a
  `NoMethodError` in our own code would have been reported to an operator as "the
  queue is unavailable". `Opanel/SilentRescue` (M00-09) caught it.
- **Ação:** narrowed to `ActiveRecord::ActiveRecordError`. The alternative —
  adding a disable comment — would have been weakening a checker to keep a wrong
  behaviour, which is the thing the checker exists to prevent.
