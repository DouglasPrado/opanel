## Findings

### F-1 — Validation is hand-written rather than delegated to a JSON Schema gem

- **Dimensão:** Simplicidade
- **Severidade:** Low
- **Evidência:** `lib/gates/pack.rb` checks structure, then the rules a schema
  cannot express.
- **Ação:** deliberate. The rules that actually protect the loop — a `file` that
  exists on disk, a dependency cycle, a `done` with no reachable commit, a
  `blocked` with a diagnosis shorter than a shrug — are none of them expressible
  in JSON Schema. A library would have bought the structural half and left the
  half that matters, at the cost of a dependency. The schema file remains
  authoritative for editors and reviewers, and a spec asserts the two agree on the
  state vocabulary.

### F-2 — Annex H §4.2's "story acceptance script" has no direct equivalent

- **Dimensão:** Arquitetura
- **Severidade:** Low
- **Evidência:** the `acceptance` check verifies that every required Story is
  `done` and has a report mapping its criteria, rather than running a per-Story
  script.
- **Ação:** deliberate, and recorded because it is a divergence from the annex's
  wording. There is no per-Story acceptance script in this repository, and one
  written by the agent would be a check the agent grades — the annex's own §4.1
  rules that out. The substitute reads state the agent cannot fabricate without
  also fabricating a commit and a report.

### F-3 — The workspace guardrail runs first

- **Dimensão:** Segurança
- **Severidade:** Low
- **Evidência:** `CHECKS.first == "workspace-clean"`, asserted by a spec.
- **Ação:** deliberate. Everything after it runs commands against that workspace;
  discovering a production credential afterwards means discovering it after it was
  used. Ordering is cheap and the assertion keeps it from drifting.
