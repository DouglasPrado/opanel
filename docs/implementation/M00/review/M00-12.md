## Findings

### F-1 — The secret scan was narrowed to the staged diff

- **Dimensão:** Segurança
- **Severidade:** Medium
- **Evidência:** `bin/security --fast --staged` runs `gitleaks git --staged`
  (0.2 s) instead of `gitleaks dir .` (9.2 s).
- **Ação:** accepted, with the reasoning stated because the change reduces what a
  gate looks at. The staged diff is exactly what a pre-commit gate is asking
  about, the `security-fast` CI job still scans the whole tree *and* the history
  on every push, and the alternative was a 13-second hook — which Annex I §12.1
  names as the thing that produces bypasses. An intermediate attempt passing many
  paths to `gitleaks dir` was wrong: that command takes a single path, and a
  secret scan that silently scans the wrong thing is worse than a slow one.

### F-2 — The boundary was widened by four files

- **Dimensão:** Escopo
- **Severidade:** Low
- **Evidência:** `bin/security`, `bin/test`, `bin/test-metadata` and
  `spec/spec_helper.rb` were added to M00-12's entry in `boundaries.yml`.
- **Ação:** deliberate, recorded in the file itself with the reason. AC9 requires
  a measured budget; the measurement was 13 s; the Story's own failure scenario
  prescribes narrowing scope. This is the mechanism working as intended — the
  widening had to be written down before the commit would pass its own gate.

### F-3 — A nested `bin/test` was overwriting the outer run's evidence

- **Dimensão:** Correção
- **Severidade:** High (resolved)
- **Evidência:** a 508-example run recorded itself as one example, because a
  `:slow` spec spawns `bin/test` against a planted failure and both wrote
  `tmp/test-results/rspec.xml`.
- **Ação:** every run now has its own id. This matters beyond the tidiness: the
  post-commit gate reads that file as evidence the suite ran against what was
  committed, so a probe's result could have stood in for the real one — including
  a probe that failed.

### F-4 — Commits made before this Story report as unverified

- **Dimensão:** Operação
- **Severidade:** Low
- **Evidência:** `bin/gate post-commit` on any commit before `65c3f0f` reports no
  pre-commit record.
- **Ação:** accepted as accurate. The gate can only speak for commits made after
  the hook existed, and backfilling records would be manufacturing evidence for
  checks that never ran.
