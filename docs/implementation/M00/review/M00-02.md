## Findings

### F-1 — The Migration Gate parses source text rather than the migration object

- **Dimensão:** Simplicidade / Correção
- **Severidade:** Medium
- **Evidência:** `lib/gates/migration_gate.rb` — rules match regular expressions
  against migration source.
- **Ação:** deliberate, with a known limit. The gate must run in the Pre-commit
  Gate before a database exists and must report file, line and rule instead of
  raising from inside Active Record. Text matching means a sufficiently creative
  migration can evade it — for example building an operation name dynamically. The
  gate is a guard against accident, not against an adversary, and it is one of
  several layers: the migration still has to pass review and CI. Comment lines are
  skipped and `reversible do` blocks are honoured, which removes the two obvious
  false-positive classes. Raising the ceiling would mean parsing Ruby, which is a
  Story of its own if evasion ever shows up in practice.
- **Estado:** closed — accepted limitation, recorded here rather than hidden.

### F-2 — `infrastructure_checkpoints` uses a bigint key while ADR-0002 is pending

- **Dimensão:** Dados
- **Severidade:** Low
- **Evidência:** `db/migrate/20260906120000_create_infrastructure_checkpoints.rb`.
- **Ação:** correct under either outcome of the ADR. ADR-0002 §1 scopes the ULID
  key to *domain* tables, and this table is neither a domain entity nor exposed
  through the API, MCP or Swarm labels. The rationale is written into the migration
  itself so a later reader does not mistake it for a precedent.
- **Estado:** closed

### F-3 — `ci` cannot boot without `SECRET_KEY_BASE`

- **Dimensão:** Operação
- **Severidade:** Low
- **Evidência:** `RAILS_ENV=ci bin/rails runner 'puts 1'` →
  `Missing 'secret_key_base' for 'ci' environment`.
- **Ação:** intended. Failing closed on missing configuration is the required
  behaviour (Annex I §2), and this is the direct consequence of removing the unused
  master key in M00-01. The residual issue is only the wording — Rails suggests
  `credentials:edit`, while Opanel expects an environment variable. M00-16 owns the
  typed configuration contract and the actionable message; recorded as a pendency
  in the Story Report and in M00-01's F-2 so it cannot be lost.
- **Estado:** open, owned by `M00-16`
