## Findings

### F-1 — Waiving the secret scan requires recorded human approval

- **Dimensão:** Segurança
- **Severidade:** Low
- **Evidência:** `HUMAN_APPROVAL_REQUIRED = %w[secret-scan]` in
  `lib/gates/security_waivers.rb`.
- **Ação:** deliberate. Every other finding class can be waived by an engineer
  with an owner and a deadline. The secret scan cannot, because it is the one
  control between a leaked credential and a green build, and an autonomous agent
  that can waive it can waive it at 3am.

### F-2 — The allowlist names fixture values, not spec files

- **Dimensão:** Segurança
- **Severidade:** Low
- **Evidência:** `config/security/gitleaks.toml` `regexes` lists sixteen specific
  values; `paths` excludes no security spec.
- **Ação:** deliberate, and the more laborious of the two options. Allowlisting
  `spec/security/` wholesale would also hide a real secret that ended up there —
  precisely the case most worth catching. The cost is one line per fixture.

### F-3 — Planted fixtures had to be made deterministic

- **Dimensão:** Testes
- **Severidade:** Medium (resolved)
- **Evidência:** an earlier version generated fixtures with `SecureRandom` and was
  intermittently green: gitleaks applies an entropy threshold that a random string
  sometimes falls below.
- **Ação:** fixed values assembled from fragments. A flaky security test is a
  defect, and retrying it would have converted a real gap in the scan into a
  slower suite.
